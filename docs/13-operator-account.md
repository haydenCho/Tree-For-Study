# 운영자 계정 안내

## 현재 상태
- 운영자 계정은 아직 없다(개발 DB 사용자 0명, 2026-10-17 확인).
- 기본 운영자 계정이나 기본 비밀번호는 코드에 두지 않는다. 서버에서 CLI로 직접 만든다.
- 테스트 중 만든 운영자 계정은 모두 별도 테스트 DB(tfs-e2e, tfs-prod)에만 있었고, 점검 후 DB째 삭제했다.

## 운영자 계정 만들기
```bash
# 개발 스택
docker compose exec backend python -m app.cli create-operator --email 본인이메일 --real-name 실명 --display-name 숲지기

# 운영 서버(EC2)
docker compose -f compose.production.yaml exec backend python -m app.cli create-operator --email 본인이메일 --real-name 실명 --display-name 숲지기
```
- 실행하면 비밀번호(12~128자)를 두 번 입력받는다. 입력값은 화면·로그에 남지 않고 Argon2id 해시로만 저장된다.
- 비밀번호는 명령줄 인자로 받지 않는다(셸 기록에 남지 않도록).
- 만들어진 계정은 승인 절차 없이 바로 `active` 상태의 운영자다.

## 운영자 계정의 특징
- 활성 멤버 정원 10명에 운영자도 포함된다. 운영자 1명이면 멤버는 9명까지 승인할 수 있다.
- 로그인하면 사이드바에 **운영자 설정**(`/admin`)이 생긴다.
  - 가입 승인·거부, 멤버 중지(중지 즉시 기존 로그인 해제)
  - 초대 코드 발급·폐기
  - 도서관 IP 등록과 '서버가 본 접속 IP' 진단
  - 휴무일·대면일 지정, 출석 정정(사유 필수)
- 멤버의 실명·이메일은 운영자만 볼 수 있다. 공동 숲에는 표시 이름과 이모지만 보인다.
- 운영자는 자기 자신을 중지할 수 없고, 운영자 화면에는 다른 운영자를 중지하는 버튼이 없다.
- 운영자를 더 두려면 CLI를 다시 실행한다.

## 계정을 만든 다음
1. 초대 코드를 발급한다(운영자 화면 또는 CLI).
   ```bash
   docker compose exec backend python -m app.cli create-invite --max-uses 10 --ttl-days 7
   ```
   코드 원문은 발급할 때 한 번만 보여 주고 DB에는 해시만 저장되므로 바로 복사해 둔다.
2. 멤버가 그 코드로 가입하면 **승인 대기** 상태가 된다.
3. 운영자 화면에서 실제 멤버인지 확인하고 승인한다.

## 비밀번호를 잊었을 때
비밀번호 재설정 기능은 아직 없다. 지금은 운영자가 직접 처리해야 하며, 필요하면 재설정용 CLI 명령을 추가한다.
